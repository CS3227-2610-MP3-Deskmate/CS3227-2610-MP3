# 3-sign-in-by-role

Goal: Users sign in with a username and password, land on their role's page and sign out, and the server refuses role pages to signed-out visitors and to the other role, meeting ACC-1.1–1.8 in about 200 changed lines under `src/`, not counting tests and migrations.

- [x] **implementer**: Add accounts, signing in and out, and the role pages. Makes `test_sign_in.py`, `test_sign_out.py`, `test_role_pages.py`, `test_sessions.py` and `test_home_session_cookie_database_down_returns_placeholder_page` pass (ACC-1.1–1.7), and keeps the PLT tests passing.
  - New app `src/deskmate/accounts/` (label `accounts`, no `apps.py`), which owns users, workspaces, signing in and out, and the role pages.
  - `models.py`: `Workspace` with no fields of its own. `User(AbstractUser)` adds a `role` field whose `TextChoices` are `requester` ("Requester") and `support_officer` ("Support Officer"), a required `workspace` foreign key with `PROTECT`, and a check constraint that `role` is one of the two. `AbstractUser` already gives unique 150-character usernames with Django's Unicode validator, NFKC in `create_user`, and salted password hashes.
  - `migrations/0001_initial.py`: generated by `makemigrations accounts` under `deskmate.tests.settings`, not written by hand.
  - `forms.py`: `SignInForm(AuthenticationForm)`. It replaces the username field with a plain `CharField`, which strips whitespace, and `clean_username` then applies NFKC. Django's `UsernameField` skips NFKC for input longer than 150 characters, so the `150-after-nfkc` case fails with it. Remove the `maxlength` that `AuthenticationForm` sets on the username input, because ACC-1.7 measures length after NFKC, and set `use_required_attribute = False`, so the browser does not block empty fields. Both follow ACC-1.3, which needs every submission to reach the server.
  - `views.py`, function views like those in `deskmate/views.py`:
    - `sign_in`: decorated with `sensitive_post_parameters`, then `require_http_methods(["GET", "POST"])`, so other methods get 405 before the signed-in redirect. A signed-in user goes to their own role's page. A valid form goes to Django's `login()`, which replaces the session key, then redirects the same way. It never reads `next`. Not `LoginView`, because that redirects signed-in users before it checks the method, and it follows `next`.
    - `sign_out`: `require_POST`, Django's `logout()`, then a redirect to `sign-in`.
    - `role_page(request, role)`: `require_GET`, then `login_required(login_url="sign-in", redirect_field_name=None)`. If the stored role differs, a 403 from `forbidden.html` with `This page is not for your role.`; otherwise the page, titled with the role's label. Both the role pages and the sign-in redirects use one map from role to URL name.
  - Templates in `accounts/templates/accounts/`: `base.html` (title and one `h1`), `sign_in.html`, `role_page.html` and `forbidden.html` (one `<p>` with the message), using the exact texts of ACC-1.1–1.5. If the form has any error, the sign-in page shows only `Incorrect username or password.`: no field errors, and both labels joined to their fields by `for`/`id`.
  - `src/deskmate/urls.py`: add `sign-in/`, `sign-out/`, `requester/` and `support/`; each role page gets its role as an extra URL argument.
  - `src/deskmate/settings.py`:
    - Apps: `deskmate.accounts`, `django.contrib.auth`, `contenttypes` and `sessions`.
    - Middleware: the session, CSRF and authentication middleware around `CommonMiddleware`, in Django's order.
    - `AUTH_USER_MODEL = "accounts.User"`, and `DEFAULT_AUTO_FIELD`.
    - Sessions: `SESSION_COOKIE_AGE` of 8 hours with `SESSION_EXPIRE_AT_BROWSER_CLOSE`.
    - Cookies: `SESSION_COOKIE_SECURE` and `CSRF_COOKIE_SECURE` whenever debug is off.
    - `CSRF_TRUSTED_ORIGINS`: `https://<host>` for each allowed host. It is ACC-1.8's origin rule, but it is needed here because every test submission sends that origin over plain HTTP. `SECURE_PROXY_SSL_HEADER` stays unset.
  - The 8-hour limit is Django's database session expiry, which Django sets only when it saves the session. Nothing saves the session after `login()`, so activity cannot extend it; a comment in the settings says so.
- [x] **implementer**: Show the Forbidden page for CSRF failures and add the framing and caching headers (ACC-1.8). Makes `test_csrf.py` and `test_security_headers.py` pass.
  - `accounts/views.py`: `csrf_failure(request, reason="")` renders `forbidden.html` with status 403 and the ACC-1.8 message, and never shows `reason`. With `CSRF_FAILURE_VIEW`, it makes `test_csrf.py` pass.
  - New `src/deskmate/caching.py`, with docstrings for the module and its function: a function-style middleware `no_store` that adds `no-store` to every response's `Cache-Control` with Django's `patch_cache_control`. No view needs `never_cache`. It makes `test_headers_role_page_response_is_not_stored` pass.
  - `settings.py`: `CSRF_FAILURE_VIEW` points to `csrf_failure`. `deskmate.caching.no_store` and `XFrameOptionsMiddleware` (Django's default `DENY`) go first in `MIDDLEWARE`, so they also mark the responses Django and other middleware make, Django's own 400 and 500 pages included. Both apply to every route. `XFrameOptionsMiddleware` makes the two `denies_framing` tests in `test_security_headers.py` pass.
