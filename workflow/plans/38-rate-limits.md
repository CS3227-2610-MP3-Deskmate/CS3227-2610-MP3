# 38-rate-limits

Goal: Signed-out visitors' `POST /sign-in/` and `POST /demo-workspace/` are checked and counted against per-address-group and everyone limits in the database, and refused ones get the `429` page, meeting ACC-3.1–3.8 in about 180 changed lines under `src/`, not counting tests and migrations, with one additive migration and no dependency or service.

- [x] **implementer**: Check and count attempts, and refuse those over a limit (ACC-3.1–3.8). Makes `test_rate_limits.py`, `test_rate_limit_addresses.py`, `test_rate_limit_requests.py`, `test_rate_limit_failures.py` and `test_rate_limit_records.py` pass, and keeps every other test passing.
  - `accounts/models.py`: `Kind(TextChoices)`, sign-in attempt and creation, and `CountedAttempt` with only `kind`, `group` (64-character hex) and `counted_at`, as the data model's Counted attempt row says. No other field, index or relation, so deleting it is one `DELETE`.
  - `accounts/migrations/0002_countedattempt.py`: generated by `makemigrations accounts` under `deskmate.tests.settings`, not written by hand. It only creates the new table, so it is additive and code without it still runs, and it keeps Django's default `atomic = True`. No `RunSQL` or data migration. Until it is applied, attempts get `500` (ACC-3.7, operator prerequisites).
  - New `accounts/limits.py`, which owns the limits, with docstrings for the module and each function:
    - Constants: `LIMITS` by kind, per group and for everyone (10 and 30, 3 and 5), the 10-minute window, and the 5-second wait.
    - `client_address(meta)`: if `HTTP_X_FORWARDED_FOR` is in `meta`, even empty, its last comma-separated entry with only spaces and tabs stripped (`strip(" \t")`); otherwise `REMOTE_ADDR`, or `""` (ACC-3.5).
    - `address_group(text)`: `ipaddress.ip_address`, with any text holding `%` rejected first, because Python accepts zone IDs. An IPv4-mapped address becomes the IPv4 address it holds. Returns `"4 <address>"` for IPv4, `"6 <first 64 bits in hex>"` for IPv6, and one shared constant for everything else. Python already rejects leading zeros, brackets, ports and networks.
    - `_stored_group(group)`: `salted_hmac(<salt>, group, algorithm="sha256").hexdigest()`, which reads `settings.SECRET_KEY` on each call (ACC-3.6).
    - `check_and_count(request, kind)` returns `None` if the attempt is allowed and now counted, or the refusal's `Retry-After` in seconds. Everything happens in one `transaction.atomic(durable=True)`, so the check commits before the view hashes anything, and no caller can widen the transaction (ACC-3.8). In order, every statement through Django's default connection, with fixed SQL and values as parameters:
      1. `SET LOCAL lock_timeout = '5s'`.
      2. `SELECT pg_advisory_xact_lock(%s)` with one fixed key. A wait over 5 seconds raises `OperationalError`, which goes unhandled to the `500` of PLT-1.4 (ACC-3.7).
      3. The attempt's moment: `timezone.now()`, called through the module so the `clock` fixture applies, and read only once the lock is held, or this kind's latest `counted_at` if that is later (ACC-3.8).
      4. Delete this kind's records with `counted_at <= moment - window`, leaving the other kind's (ACC-3.6).
      5. For each limit, the newest `counted_at` at position `limit`, among this kind's records with `counted_at > moment - window`, from this group or from everyone (`order_by("-counted_at")[limit - 1:limit]`). If it exists, the limit refuses until it plus the window.
      6. If any limit refuses, return the latest of those times minus the moment in whole seconds, rounded up (`-(-delta // timedelta(seconds=1))`); it is 1–600 without clamping, because no record is later than the moment (ACC-3.3). Otherwise create one `CountedAttempt` at the moment and return `None`.
    - One lock serves both kinds. Now that each kind reads and deletes only its own records, a lock per kind would also meet ACC-3.8, but one shared lock is simpler: one fixed key and no mapping from kind to key. The cost is that attempts of both kinds wait in turn, which ACC-3.8 allows.
  - `deskmate/views.py`: generalise `forbidden` into `message_page(request, title, message, status)`, which `forbidden` calls. Rename `templates/deskmate/forbidden.html` to `message.html` (`git mv`); its content does not change.
  - `accounts/views.py`: a decorator `rate_limited(kind)`. For a signed-out visitor's `POST`, it calls `check_and_count` and, if the attempt is refused, returns `message_page` with `Too many attempts`, the kind's ACC-3.2 text and `429`, and sets `Retry-After`. Anything else goes straight to the view, so a signed-in user's redirect is never counted (ACC-3.4). Put it just inside `require_http_methods` on `sign_in` and inside `require_POST` on `demo_workspace`. Both views stay as they are, and CSRF and 405 come first, as Routes says. Add ACC-3 to the module docstring. The middleware already adds `no-store` and `DENY` to the `429`.
  - No change to settings: `ATOMIC_REQUESTS` stays off, so nothing holds the lock while hashing.
